用 Tauri 写一个 Hello World：从环境配置到打包踩坑记录

为什么折腾 Tauri

以前想用前端技术写桌面应用，基本只有 Electron 可选。虽然生态成熟、轮子多，但缺点也很明显：自带 Chromium 和 Node.js，空项目打包出来就有一两百兆，跑起来开几个窗口内存就上去了。

Tauri 的思路不太一样，它不打包浏览器内核，而是直接调用操作系统自带的 WebView（Windows 下用 Edge WebView2，Mac 下用 WebKit），后端换成了 Rust。这样搞出来的可执行文件一般只有几兆到十几兆，内存占用也低得多。

而且 Rust 部分并不需要你上来就精通生命周期或者异步运行时，对于绝大部分功能，Rust 端只充当一个提供本地系统 API 的“后端”，页面 UI 依然是纯前端。

1. 本地环境准备

Tauri 依赖底层的 C/C++ 编译链和 Rust 环境，所以第一步得把编译工具装好。

  • Node.js: 随便装个 18+ 或 20+ 的 LTS 版本就行。
  • Rust:
    • 官网下载 rustup-init.exe（Windows）或者终端执行脚本安装。
    • 装完后终端跑 cargo --version 和 rustc --version，能正常输出版本号就行。
  • C++ 编译工具链（Windows 用户重点）:
    • 需要安装 Visual Studio 2022 生成工具（Build Tools）。
    • 安装时勾选“使用 C++ 的桌面开发”，否则第一次 cargo build 时会直接报缺少链接器或 MSVC 环境的错误。
  • WebView2:
    • Win10 较新版本和 Win11 默认自带，如果是较老的系统需要去微软官网下个 Evergreen 运行时。

3. 项目结构说明

创建出来的项目目录结构非常清晰，核心就两层：

  • **src/**：完全是常规的前端静态资源。
  • **src-tauri/**：桌面壳子。包括窗口怎么开、透明度、尺寸、以及给前端暴露什么本地接口。

7. 几个常见踩坑点

  1. Windows 编译报错缺少 link.exe 或 C++ 运行库

    • 原因：本机只有 Rust，没有装 Visual Studio C++ 生成工具。
    • 解决：下载 Visual Studio Installer，勾上“使用 C++ 的桌面开发”装完重启终端。

  2. tauri.conf.json 中的 devPath 别写成 ../

    • 很多新手把 devPath 直接指到项目根目录 ../，这会导致 cargo build 时 Tauri 把整个项目（包括 src-tauri/target 下的锁文件）都当成前端资源扫描，从而在 Windows 下报 os error 33（文件被占用）死锁。
    • 正确做法：只指向前端代码目录，比如 ../src 或 ../dist。

  3. 前端调用 invoke 时参数名对不上

    • Rust 里的入参叫 name: &str，前端传参必须是 { name: 'xxx' }。如果传了未定义的 key，Rust 序列化会解析成空或者直接报错。

  4. 不想引入 @tauri-apps/api 依赖也可以直接调用

    • 只要在 tauri.conf.json 里开启 "withGlobalTauri": true，Tauri 就会在所有网页全局注入 window.__TAURI__。
    • 前端无需 npm 安装任何包，直接写 window.__TAURI__.tauri.invoke(...) 就能跑。

总结

Tauri 的上手成本没有网上传的那么高。你不需要真的去啃透 Rust 的复杂特性，日常开发大部分工作还是在写前端代码。当需要操作系统底层特权或者本地高性能计算时，再在 Rust 里写一两个函数暴露给前端即可。对于轻量级桌面工具、小玩具或者桌面挂件类项目，Tauri 是个很舒适的选择。
